# Site PTT / PBVi (glisser-déposer)

Petit site **local** qui utilise `ptt_pipeline.py` sans rien changer aux calculs.
Il tourne uniquement sur votre ordinateur (adresse `127.0.0.1`, inaccessible depuis le réseau) : les DICOM ne quittent pas la machine.

## Installation (une seule fois)
Rien de plus que pour le pipeline (Python 3 + `pydicom numpy scipy pandas matplotlib openpyxl`, voir le guide, chapitre 5).
Gardez ces fichiers **ensemble dans un même dossier** :
- `site_ptt.py` (le serveur)
- `page_site_ptt.html` (la page)
- `bolustrak_ptt.py` (analyse 2D BolusTrak, facultatif)
- `ptt_pipeline.py` (votre pipeline, version 1.3.4 ; vous pouvez le remplacer par une version plus récente)
- `Lancer_site_PTT.bat` (Windows) / `Lancer_site_PTT_Mac.command` (Mac)

## Version en ligne (rien à installer)
**Ouvrir l'outil : https://bencardio.github.io/ptt-auto/** (Chrome ou Edge récents).

- Mêmes calculs que le site local (`ptt_pipeline.py` et `site_ptt.py` chargés tels quels), exécutés **dans le navigateur** par Python (Pyodide) : les DICOM sont lus sur place, rien n'est envoyé à un serveur.
- Toujours la dernière version : chaque modification du dépôt est en ligne quelques minutes plus tard.
- Au premier lancement, choisissez un **dossier de travail** vide (par ex. `PTT_resultats`, pas celui des DICOM) : résultats, `pseudonymes.csv`, `prefixe_pseudo.txt` et `cliniques.xlsx` y sont enregistrés comme à côté du site local. Les fois suivantes, « Reprendre » (ou rien, si Chrome a reçu « Autoriser à chaque visite »).
- « Choisir un dossier sur ce PC et analyser » : le navigateur demande d'autoriser la lecture du dossier ; une cohorte entière se choisit de la même façon (option « un sous-dossier par patient »). Le champ « chemin à coller » n'existe pas en ligne.
- Plus lent que le site local (Python dans le navigateur) ; premier chargement environ 1 minute, ensuite en cache. La page reste utilisable entre deux patients.
- Code de la version en ligne : `web/` (`pont.js` côté page, `worker.js` et `web_ptt.py` côté Python). `page_site_ptt.html` est la même page pour les deux versions.

## Site local : mises à jour automatiques (dépôt GitHub)
Le code est sur GitHub (dépôt `Bencardio/ptt-auto`). À chaque lancement par `Lancer_site_PTT.bat` ou `Lancer_site_PTT_Mac.command`, `mise_a_jour.py` télécharge la dernière version et remplace uniquement les fichiers du programme : rien à télécharger, décompresser ni autoriser.
- Les résultats, copies DICOM, `pseudonymes.csv`, `cliniques.xlsx`, etc. ne sont jamais touchés ni envoyés : la mise à jour ne fait que **télécharger** du code.
- Les fichiers remplacés sont gardés dans `anciennes_versions/<date_heure>/` (pour revenir en arrière, recopiez-les à côté de `site_ptt.py`).
- Sans internet, ou si le réseau de l'hôpital bloque GitHub, le site démarre normalement avec la version déjà installée.
- Les lanceurs (.bat, .command) eux-mêmes ne sont pas mis à jour automatiquement.
- Dépôt privé : la mise à jour automatique sans mot de passe ne fonctionne qu'avec un dépôt public (le code ne contient aucune donnée patient ; le `.gitignore` empêche d'y ajouter résultats et DICOM).

## Lancement
- **Windows** : double-cliquez sur `Lancer_site_PTT.bat`.
- **Mac** : double-cliquez sur `Lancer_site_PTT_Mac.command` (la 1re fois : clic droit > Ouvrir).
- Ou dans l'invite de commandes, depuis le dossier : `python site_ptt.py`

Le navigateur s'ouvre sur http://127.0.0.1:8765. Laissez la fenêtre noire ouverte pendant l'utilisation ; fermez-la pour arrêter le site.

## Utilisation
1. **Le plus rapide : « Choisir un dossier sur ce PC et analyser »**. Une fenêtre Windows s'ouvre (parfois derrière le navigateur) ; les DICOM sont lus sur place, sans copie.
   Sinon, **glissez** un ou plusieurs dossiers patients dans le cadre : les fichiers sont alors d'abord copiés dans `site_travail/`, ce qui prend plus de temps pour un examen complet (plusieurs milliers d'images).
   - *Chaque dossier déposé = un patient* : le nom du dossier devient le code patient (P001, CMH-012…).
   - *Un sous-dossier par patient* : pour déposer d'un coup le dossier `dicom` du projet (choisi automatiquement si le dossier s'appelle `dicom`).
   - La liste des patients détectés s'affiche avant l'envoi : vérifiez-la.
2. Facultatif (Options) : déposez `cliniques.xlsx` (colonnes ID, Taille_cm, Poids_kg, VES_VD_mL, VES_VG_mL, FC) pour obtenir le **PBVi**. Un `cliniques.xlsx` placé à côté de `site_ptt.py` est aussi utilisé automatiquement.
3. Cliquez **Envoyer et analyser**. La progression s'affiche patient par patient.
4. Résultats : tableau PTT pic / centroïde, PTTc, PBVi, RR, alertes. Cliquez une ligne pour voir **l'image de contrôle**, la liste des séries, et relancer le patient avec **une autre série ou coupe** (remplace `choix_series.csv`).
5. **Exports** : CSV (même format que `resultats_PTT.csv`, compatible avec le mode `importer`), Excel (avec l'inventaire des séries), ou ZIP avec les images de contrôle.

### Cohorte entière (centaines de patients)
Le glisser-déposer copie les fichiers. Pour toute la cohorte, ouvrez *Options > Cohorte entière* et collez le chemin du dossier
qui contient un sous-dossier par patient (par ex. `D:\PTT_projet\dicom`) : rien n'est copié, l'analyse lit directement les fichiers.

### Analyse 2D BolusTrak
En haut de la page, choisissez **« 2D BolusTrak »** au lieu de « Perfusion » avant de choisir le dossier. Le site cherche la série BolusTrak (nom contenant bolustrak, bolus, smartprep, fluoro, timing…) et mesure le transit AP/cœur droit → VG/aorte : **pied** (arrivée du bolus), **pente maximale**, et **pic** seulement s'il est atteint. Les colonnes « Pente VG atteinte » / « Pic VG atteint » disent si la série a duré assez longtemps ; si la pente n'est pas atteinte, le statut est « non mesurable ». Patient sans cette série : « sans BolusTrak ».
Mesure différente du PTT de perfusion (non validée comme équivalente) : résultats dans un dossier à part (`resultats_site/<date>_bolustrak/resultats_bolustrak.csv`). Pas de RR, donc ni PTTc ni PBVi.

## Où sont les fichiers ?
- `resultats_site/<date_heure>/` : `resultats_PTT.csv` (mis à jour après chaque patient), `inventaire_series.csv`, `controles/*.png`, `journal_erreurs.txt` si besoin.
- `site_travail/<date_heure>/` : copies des DICOM déposés. Bouton **« Effacer les copies DICOM »** en bas de page (les résultats restent).

## Bon à savoir
- Perfusion à 3-4 coupes (pipeline 1.4.8) : quand plusieurs perfusions sont trouvées et que l'une n'a que 3 ou 4 coupes (souvent « 3 sl » dans le nom) alors que les autres en ont davantage (en général 8), c'est elle qui est analysée (les perfusions de stress restent écartées). Sur une perfusion à 3 ou 4 coupes, la coupe du milieu (2 sur 3, 2 sur 4) est retenue dès qu'elle est exploitable ; sinon une autre coupe est prise et la colonne `choix_serie` le signale. Réglages en haut de `ptt_pipeline.py` : `PREFERER_PERFUSION_PEU_DE_COUPES` (False = ancien comportement) et `N_COUPES_MAX_PREFEREE`. Le choix manuel de série ou de coupe sur le site reste prioritaire.
- Préfixe des codes pseudonymes (site 1.4.7) : dans « Options », champ « Préfixe des codes pseudonymes » (ex. `PTT-IMM-`), puis « Appliquer ». Le préfixe est gardé pour les analyses suivantes et appliqué aux patients de l'analyse affichée ; chaque préfixe a sa propre numérotation (PTT-IMM-001, 002…) et un patient garde le même code pour un même préfixe. Les correspondances sont dans `pseudonymes.csv` (colonnes ID, code_pseudo, prefixe), qui contient les noms et ne doit pas quitter l'hôpital.
- Identités des patients (pipeline 1.4.7) : fichier `identites_patients.csv` à côté des résultats (et onglet « Identites » de l'export Excel, bouton « Identités des patients (CSV) » sur le site) : une ligne par patient avec `nom`, `prenom` (pris dans le nom DICOM du patient, sinon dans le nom du dossier ; colonne `source_nom`), `identifiant`, `date_naissance`, `age_ans`, `sexe`, `date_examen`, `heure_examen`. Pour une analyse faite avec une version antérieure, le site lit un seul en-tête DICOM par patient pour le compléter (il faut que les dossiers DICOM soient encore accessibles). Données nominatives : ce fichier ne doit pas quitter l'hôpital.
- Corrections pendant l'analyse (site 1.4.7) : pendant qu'une cohorte est analysée, on peut ouvrir un patient déjà fait, cocher une autre série, saisir une coupe, utiliser l'éditeur de ROI et la fenêtre de temps : le panneau n'est plus effacé par le rafraîchissement du tableau. « Relancer ce patient » est fait tout de suite, en parallèle (sans attendre la fin du patient en cours) ; la barre de progression affiche « relance manuelle : … ».
- Fenêtre de temps analysée (pipeline 1.4.6) : dans l'éditeur de ROI, « Fenêtre analysée de … s à … s » choisit les images utilisées pour les pics, centroïdes et largeurs à mi-hauteur (ex. couper une 2e injection ou une recirculation). Tapez les valeurs, ou cliquez sur le graphique : la limite la plus proche s'y place ; les zones grisées sont exclues et le PTT d'aperçu suit. « Fenêtre automatique » revient au premier passage détecté. « Recalculer ce patient avec ces réglages » applique la fenêtre ; si les ROI n'ont pas été touchées, elles restent automatiques (placées sur tout le premier passage). Colonnes `fenetre_analyse_s` et `fenetre_manuelle`. En mode Courbes (Segment ou sauvegardées), les mêmes champs sont au-dessus de « Recalculer ce patient ».
- Courbes sauvegardées (pipeline 1.4.6) : chaque analyse de perfusion enregistre les courbes VD/VG de chaque patient dans `resultats_site/<analyse>/courbes/<patient>.txt` (CSV/zip compris), avec le RR, la fenêtre de premier passage, la série, la coupe et les ROI utilisées. Pour refaire les calculs plus tard sans les DICOM (programme modifié, nouveaux paramètres), choisissez « Courbes (Segment ou sauvegardées) » et déposez un ou plusieurs de ces fichiers : pics, centroïdes, LMH, PTTc… sont recalculés sur exactement les mêmes courbes (résultats identiques si le programme n'a pas changé). Pour changer les ROI ou la coupe, il faut en revanche repartir des DICOM. `RECALCULER_FENETRE_COURBES = True` recalcule aussi la fenêtre de premier passage. Les fichiers portent le nom du dossier du patient : ils restent à l'hôpital.
- Taille des ROI (pipeline 1.4.6) : les ROI automatiques VD et VG ont la même taille (rayon de la plus petite des deux cavités ; `FACTEUR_TAILLE_ROI` en haut de `ptt_pipeline.py` pour les agrandir ou les réduire toutes). Dans l'éditeur de ROI, chaque ROI a son propre réglage (− / curseur / +, rayon affiché en pixels et en mm) ; faire glisser en dessinant change seulement la ROI dessinée. « Taille par défaut (VD = VG) » remet la taille commune du programme. Les courbes et le PTT d'aperçu suivent chaque changement ; « Recalculer ce patient avec ces ROI » applique les tailles choisies.
- Nom, prénom et identifiant : tous les tableaux exportés (CSV, Excel, séquences) ont trois colonnes `nom` (premier mot du nom du dossier du patient), `prenom` (tout le reste, prénoms composés compris) et `identifiant` (le mot qui commence et finit par une lettre avec des chiffres entre les deux, ex. A1234567B, retiré du prénom ; s'il n'est pas dans le nom du dossier, il est pris dans l'en-tête DICOM PatientID quand celui-ci a cette forme). Espaces, « _ » et « ^ » séparent les mots. Un nom composé (ex. « LE GALL ») est donc coupé : corrigez-le à la main. Supprimez ces colonnes avant tout partage hors de l'hôpital.
- Informations d'examen (pipeline 1.4.6) : le fichier de résultats contient aussi, quand les en-têtes DICOM les donnent, `date_examen` et `date_naissance` (JJ/MM/AAAA), `age_ans` (âge à l'examen), `sexe`, `taille_cm_dicom`, `poids_kg_dicom`, `IMC_dicom`, `SC_dicom_m2` (Mosteller), l'heure d'examen, l'IRM (fabricant, modèle, champ) et l'injection (produit, volume, dose totale, concentration, débit, durée, heure de début, voie : champs DICOM « Contrast/Bolus », souvent vides si l'injecteur n'est pas relié à l'IRM). Le PBVi utilise la surface corporelle du fichier clinique, sinon celle des en-têtes (colonne `source_SC`). La date de naissance est identifiante : supprimez la colonne avant de partager les résultats, ou mettez `EXTRAIRE_DATE_NAISSANCE = False` en haut de `ptt_pipeline.py` (l'âge reste).
- Séquences réalisées (pipeline 1.4.6) : deux fichiers à côté des résultats (et deux onglets dans l'export Excel). `sequences_realisees.csv` : une ligne par patient, une colonne 0/1 par type (ciné 2, 3, 4 cavités, petit axe, valve aortique, VD ; tagging ; T1 natif, T1 post-gado ; ECV ; T2 ; T2* ; T2/STIR ; perfusion, stress, repos ; TI scout ; EGE ; LGE ; flux 2D et 4D ; angiographie ; morphologie), plusieurs séries du même type comptant une fois. `sequences_detail.csv` : chaque série avec le type retenu et comment il a été reconnu, pour vérifier. Le type vient du nom de la série (mots modifiables dans `MOTS_SEQUENCES`). Les cinés sans incidence dans le nom (ex. « CINE sBTFE_BH ») sont classés d'après l'orientation des coupes par rapport au petit axe (mention « orientation, à vérifier ») ; une T1 est « post-gado » si son nom le dit ou si elle est acquise après la 1re série avec gadolinium (perfusion, angio, TI scout, LGE). Les séries non reconnues sont listées dans `series_non_classees`. Aussi produit par `python ptt_pipeline.py inventaire`.
- Recalcul rapide : quand on recalcule un patient sur la même série (ROI redessinées, autre coupe), le site reprend les en-têtes déjà lus de cette série au lieu de relire tout l'examen (aussi après réouverture d'une analyse). « Relancer en automatique » ou une autre série relisent l'examen. Le champ commentaire reste utilisable pendant une analyse en cours.
- Temps des exports Segment (pipeline 1.4.5) : Segment exporte parfois un temps faux (ex. 40 images sur 0,55 s). Le site le détecte et reconstruit le temps avec l'intervalle réel entre images : celui de l'analyse de perfusion du même patient (même nom ; colonne `intervalle_images_s`, à partir de la version 1.4.5), sinon le champ « Intervalle réel entre images » du mode Courbes Segment, sinon 1 image par battement (alerte). Un onglet unique nommé Sheet1/Feuil1 prend le nom du fichier comme identifiant. La fenêtre du premier passage est aussi appliquée aux courbes Segment (une 2e montée tardive est exclue).
- Classeur Excel accepté aussi (pipeline 1.4.4) : en mode « Courbes Segment », un fichier .xlsx avec un onglet par patient (nom de l'onglet = code du patient) ; dans chaque onglet, 1re colonne « Temps (s) » ou « Time [ms] » (sans unité : ms si le pas dépasse 50), puis une colonne VD (ou RV) et une colonne VG (ou LV), dans n'importe quel ordre. Le format « ROI Analysis » collé tel quel dans un onglet marche aussi. Les onglets de moins de 8 lignes de données sont ignorés.
- Courbes Segment dans le site : en haut, choisir « Courbes Segment », puis glisser les exports « ROI Analysis » (.txt, un par patient, nommé comme le patient) ou le dossier qui les contient (ou « Choisir le dossier des exports »). Chaque export doit avoir une ROI VD (RV) et une ROI VG (LV). Résultats à part (`resultats_PTT_segment.csv`), mêmes colonnes que la perfusion, cases ok/échec, commentaires, image de contrôle par patient. RR : fichier clinique (RR_ms ou FC), sinon RR lu dans les en-têtes DICOM lors d'une analyse de perfusion du même patient (même nom) faite sur ce PC, sinon intervalle entre images s'il est entre 0,3 et 2 s.
- Courbes de Segment (pipeline 1.4.3) : mêmes calculs (PTT pic/centroïde, PTTc, Bazett, LMH, rapport VG/VD, alerte d'écart) sur les exports « ROI Analysis » : mettre un .txt par patient dans `exports_segment/` à côté de `ptt_pipeline.py`, puis `python ptt_pipeline.py segment` (hors site) ; résultats dans `resultats/resultats_PTT_segment.csv`. L'alerte « plateau (saturation probable) » ne se déclenche plus sur une courbe simplement large (dispersée), seulement sur un sommet vraiment écrêté.
- Méthode de calcul détaillée (PTT pic, PTT centroïde, normalisations, largeurs à mi-hauteur, rapport VG/VD, seuils) : `Methode_calcul_PTT.docx`.
- Dispersion VG/VD (pipeline 1.4.2) : colonnes `LMH_VD_s`, `LMH_VG_s` (largeur à mi-hauteur de chaque courbe, mesurée sur les points), `rapport_LMH_VG_VD`, `courbes_propres` (1 = ajustement R2 ≥ 0,90, sommet non écrêté, courbe qui redescend sous 50 %) et `dispersion_VG` (« VG étalé » si courbes propres et rapport ≥ `RAPPORT_LMH_ETALE` = 1,8). Colonne « VG/VD largeur » dans le site. L'alerte d'écart centroïde-pic (seuil `ECART_PIC_CENTROIDE_MAX_S` = 1,5 s) dit maintenant si l'écart est plutôt physiologique (courbes propres, VG étalé) ou une erreur de mesure (avec la raison). Seuils empiriques, non publiés : à ajuster sur vos témoins, en haut de `ptt_pipeline.py`. « VG étalé » seul ne fait pas passer un patient « à vérifier ».
- Fréquence cardiaque et PTT normalisés (pipeline 1.4.1) : la FC est lue dans l'en-tête DICOM de la perfusion (HeartRate chez Philips, NominalInterval = RR chez GE), sinon prise dans le fichier clinique ; colonnes `FC_bpm`, `RR_ms`, `source_RR`. `PTTc_pic` / `PTTc_centroide` = PTT normalisé au cycle cardiaque (PTT / RR = PTT × FC / 60, en nombre de battements). `PTT_bazett_pic` / `PTT_bazett_centroide` = PTT corrigé de la FC selon Bazett (PTT / √RR, RR en s), comme le QTc.
- Code pseudonyme : chaque patient reçoit un code stable (PTT-001, PTT-002…), affiché à côté de son nom et dans la colonne `code_pseudo` des exports (le nom reste dans `ID`). La correspondance est gardée dans `pseudonymes.csv` à côté du site : le même patient garde son code d'une analyse à l'autre, perfusion comme BolusTrak. Ce fichier contient les noms : il ne doit pas quitter le PC de l'hôpital. Pour partager des résultats, supprimez la colonne `ID` de l'export.
- Commentaire : champ libre en haut du panneau du patient (raison d'exclusion, artefact…), enregistré en quittant le champ ou avec Entrée, visible dans le tableau et dans la colonne `commentaire` des exports. Il est conservé si le patient est relancé.
- Reprendre une analyse : chaque analyse est enregistrée au fur et à mesure (`resultats_site/<analyse>/etat_lot.json`). Après avoir fermé le site, relancez-le : le cadre « Reprendre une analyse précédente » en haut de la page liste les analyses, avec le nombre de patients encore « à vérifier ». « Rouvrir » retrouve les résultats, les validations ok / échec et les ROI dessinées à la main. Pour relancer un patient, ses DICOM doivent toujours être au même endroit.
- Relecture au clavier : → (ou N) ouvre le patient « à vérifier » suivant avec son éditeur de ROI, ← (ou P) le précédent, O = ok, E = échec (puis passage automatique au suivant), Échap ferme le panneau. Les touches sont ignorées pendant la saisie dans un champ.
- Validation manuelle : chaque patient « à vérifier » a deux cases « ok » et « échec » (colonne Validation). Après relecture (et éventuellement correction des ROI), cochez ok pour retenir le résultat ou échec pour exclure le patient : le statut « à vérifier » est remplacé par « ok » ou « échec », à l'écran comme dans le CSV/Excel. La colonne `statut_auto` garde le statut donné par le programme et `validation_manuelle` indique les patients tranchés à la main ; décocher rétablit « à vérifier ». Une relance du patient efface sa validation, et « Relancer les échecs » ne relance pas les échecs validés à la main.
- Panneau d'un patient : il s'ouvre juste sous la ligne cliquée (image de contrôle, séries, éditeur de ROI) et se referme en cliquant à nouveau sur la ligne. L'éditeur de ROI s'y ouvre automatiquement, avec les ROI du programme.
- Forme et taille des ROI automatiques (pipeline 1.4.0) : chaque ROI est un disque centré au point le plus profond de la cavité, calculé sur le sang seulement (piliers, trabéculations et myocarde peu rehaussés exclus). Réglages : `FRACTION_NOYAU_ROI` (plus grand = ROI plus petite) et `FRACTION_REHAUSSEMENT_ROI`.
- Corriger les ROI à la main (site 1.3.8) : cliquez sur le patient, puis « Ouvrir l'éditeur de ROI ». Choisissez la coupe et une image où les cavités sont bien blanches, puis dessinez un cercle VD (bleu) et un cercle VG (rouge) : clic au centre, puis glisser pour la taille. Les courbes et un PTT pic d'aperçu se mettent à jour à chaque cercle. « Recalculer ce patient avec ces ROI » refait le calcul complet ; la colonne `ROI` vaut alors « manuelles ». « Relancer en automatique » revient aux ROI du programme.
- Détection VD/VG (pipeline 1.3.7) : seules les images du premier passage (de l'arrivée du contraste à +35 s) servent à placer les ROI et à mesurer les courbes, pour ne pas être trompé par une 2e injection pendant la série, la recirculation ou un organe abdominal qui se rehausse tard. Sur l'image de contrôle, la zone grisée est affichée mais non utilisée. Les pixels qui « clignotent » (mouvement, paroi thoracique) sont écartés, et les deux ROI doivent être des cavités voisines. Les perfusions Philips exportées en une série par dynamique (n° 120100001, 120100002…) sont regroupées automatiquement. Réglages : `FENETRE_PREMIER_PASSAGE_S`, `DISTANCE_CAVITES_OK_MM`.
- Lecture rapide (pipeline 1.4.6, pour les exports rangés une séquence par sous-dossier) : les en-têtes sont lus 8 fichiers à la fois ; dans chaque sous-dossier, seuls le premier et le dernier fichier sont lus d'abord (tous les dossiers en même temps). Un sous-dossier qui ne contient qu'une série sans intérêt (ciné, LGE, T1…) s'arrête là, de même que les perfusions dérivées (cartes, « low res ») et les perfusions de stress quand une perfusion de repos existe ; seules les perfusions utiles et les BolusTrak sont lues en entier. Sur un examen test de 986 fichiers : 256 fichiers ouverts au lieu de 625, PTT identique. Avant : il apparaît dans la liste des séries avec « [lecture partielle] ». Si vous imposez une série, le patient est relu en entier. Réglages en haut de `ptt_pipeline.py` : `N_FILS_LECTURE`, `LECTURE_RAPIDE`.
- Patients sans perfusion (pipeline 1.3.5) : si aucune série ne porte un nom de perfusion (`MOTS_PERFUSION`), le patient n'est pas analysé, son statut est « sans perfusion » et la colonne `presence_sequence_perfusion` vaut 0 (1 sinon). Pour l'analyser quand même, cliquez dessus, cochez une série et « Relancer ce patient avec ce choix ». Pour revenir à l'ancien comportement : `AUTORISER_SERIE_DE_REMPLACEMENT = True` en haut de `ptt_pipeline.py`.
- Lenteur : cliquez sur le patient, la ligne « Durée » indique le nombre de fichiers DICOM lus et le temps de lecture et de calcul. La lecture de tous les fichiers de l'examen est l'étape la plus longue ; mettre seulement les séries de perfusion dans le dossier du patient l'accélère beaucoup.
- Les réglages (mots-clés des séries, méthode principale, bornes…) restent ceux du haut de `ptt_pipeline.py`.
- Navigateurs : Chrome, Edge ou Firefox récents (le dépôt de dossiers n'existe pas sur les vieux navigateurs).
- Si le port 8765 est occupé, le site prend le suivant (8766…) : l'adresse exacte est affichée dans la fenêtre noire.
- Outil de recherche, non destiné au diagnostic clinique.
